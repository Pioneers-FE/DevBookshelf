## 45장 프로미스

### 45.1 비동기 처리를 위한 콜백 패턴의 단점

#### 콜백 헬

비동기 처리에 후속 처리를 수행하는 비동기 함수가 비동기 처리 결과를 가지고 다시 비동기 함수를 호출, 콜백 함수 호출이 중첩되어 복잡도가 높아지는 현상

#### 에러 처리의 한계

### 45.2 프로미스의 생성

Promise: 생성자 함수, 비동기 처리를 수행할 콜백 함수를 인수로 전달, 콜백 함수는 resolve(비동기 처리 성공시 호출), reject(비동기 처리 실패시 호출) 함수를 인수로 전달

#### 상태 정보

- pending: 비동기 처리 수행되지 않은 상태
- fulfilled: 비동기 처리가 수행 됨, 성공
- reject: 비동기 처리가 수행 됨, 실패

### 45.3 프로미스의 후속 처리 메서드

프로미스의 비동기 처리 상태가 변화 -> 인수로 전달한 콜백 함수가 선택적으로 호출

- Promise.prototype.then: 두 개의 콜백함수를 인수로 전달, 비동기 처리 성공 후 콜백 함수, 비동기 처리 실패 후 콜백 함수

- Promise.prototype.catch: 프로미스가 reject인 경우 실행되는 콜백 함수

- Promise.prototype.finally: 프로미스의 성공 실패 상관없이 무조건 한번 호출되는 콜백 함수

### 45.5 프로미스 체이닝

프로미스 체이닝: then, catch, finally 후속 처리 메서드는 언제나 프로미스를 반환하기 때문에 연속적 호출이 가능

### 45.6 프로미스의 정적 메서드

#### Promise.resolve, Promise.reject

- 이미 존재하는 값을 래핑, 프로미스를 생성하기 위해 사용

#### Promise.all

- 여러개의 비동기 처리를 모두 병렬 처리
- 전달된 배열의 프로미스를 병렬 처리
- 배열 중 하나의 프로미스라도 reject 되면 나머지 프로미스가 fulfilled 상태를 기다리지 않고 즉시 종료
- 모두 fulfilled 상태가 되면 처리 결과를 배열로 하여 새로운 프로미스로 반환

#### Promise.race

- all 메서드처럼 프로미스를 배열로 받음
- 가장 먼저 fulfilled 상태가 된 프로미스의 처리결과를 resolve 하는 프로미스로 반환
- reject 상태가 되면 all 메서드와 동일하게 처리

#### Promise.allSettled

- 배열로 전달받은 프로미스가 모두 settled 상태(fulfilled, reject 상태)가 되면 처리 결과를 배열로 반환

### 45.7 마이크로태스크 큐

태스크 큐와 별도 큐

프로미스 후속 처리 메서드의 콜백 함수가 일시 저장

태스크 큐보다 우선 순위가 높다

### 45.8 fetch

fetch: HTTP 응답을 나타내는 Response 객체를 래핑한 Promise 객체를 반환

HTTP 에러가 발생해도 에러를 Reject 하지 않고 OK 상태를 false로 설정한 Response 객체를 resolve

요청 완료 되지 않은 경우에만 reject
